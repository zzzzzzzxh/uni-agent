对三个独立配对、六个已开始任务重新计算后，结果与保存的分析一致：**归属进程 PSS 时间积分下降 60.7192%，整任务 p95 增加 0.9098%，配对首工具额外任务 p95 为 0.2890 秒**。六个任务全部正确，资源审计均为 `no_observed_residue`，没有遗漏或被排除的失败任务。

上述结果满足本轮进程内存、任务延迟及首工具延迟的建议门槛，前提是**精确知道合成等待的结束期限，提前 1.5 秒恢复并校验**。底层恢复加完整 oracle 仍实际耗时 **1.845–1.944 秒**，不能表述为原生恢复操作已加速。物理节点收益门槛仍是 `unverified`，整体保守判定也保持 `unverified`。正式结果与复现说明见[64 MiB 实测报告](sandbox_offload_64m_results.md)。

## 固定期限、副作用与提前驻留成本

逐条检查十二个工具事件：期限始终为同一周期 `idle_start + 30s`，日志中 `idle_eligible` 的写入与变量赋值相差数微秒，没有移动工具期限。所有 `tool_dispatched` 均晚于该期限；常驻组仍在期限之后执行完整 `/state` 校验，没有采用提前量。

卸载组的六个恢复开始时刻分别早于期限约 **1.49986 秒**。每段提前恢复窗口都覆盖十五个真实宿主采样点，其**归属进程 PSS 积分为每段 0.212–0.224 GiB·s，已完整包含在上表主积分中**，未把提前驻留、恢复或预触页内存移到观测窗口外。这是整组进程在该区间的成本，不声称全部来自业务 VM。

完整 RAM oracle 的真实恢复区间为 1.848493、1.844803、1.922188、1.944189、1.856434、1.909098 秒。提前阶段只做恢复及读取状态，改变文件、FD 偏移与计数的 `/tool` 仍在期限后才执行。因此降低的是工具到达后的等待，而非底层恢复工作量。

`tool_requested` 事件的写入发生在恢复/oracle 完成后；真正的请求到达基准是其 `ready_monotonic_seconds` 与结果中的固定 deadline。`restore_oracle_seconds` 表示 deadline 后的剩余等待，不应被解释为完整恢复耗时。核查使用固定 deadline，未用较晚的事件写入时间缩短延迟。

## 历史基线解释与适用边界

[未优化复查](../artifacts/agentenv-offload-results/baseline64-recheck-20261022T015234Z/results.jsonl)中，offload/resident 的 create 为 **14.437916/4.400611 秒**，整任务为 **81.486526/67.938220 秒**。创建差异 10.037305 秒，占整任务差异 13.548306 秒的大部分；其 +19.94% 整任务增幅不能全部归因于恢复。创建分解仅解释波动，不能将其从正式验收指标中删除。

[更早的 64 MiB 边界轮](../artifacts/agentenv-offload-results/boundary-bound1-m64-w30-20261021T155607Z/results.jsonl)的 create 已较接近：4.485176/4.418210 秒，但任务仍增加 5.132%，配对首工具额外 p95 为 1.798 秒。因此旧延迟问题也不能全部归结为创建波动。该轮一个退出竞态样本缺少证明，PSS 收益仍是未知。

跨轮源码也并非只改变一个变量：正式组的探针改为使用 memoryview 对完整内存执行相同 SHA-256，去除旧的逐块临时复制；Demo 增加显式提前恢复，采样器修复退出证据。归档摘要保留了这些差异。正式轮内部 A/B 使用相同源码和环境，比较有效；不能把跨轮总差值称作只有提前量这一项造成的原生恢复加速。

本结论限于单节点、暖缓存、64 MiB 低熵且不改写的工作集、已知固定期限和两周期任务。三个独立配对仅提供探索性证据，不足以证明生产尾延迟或成功率 SLA，也未验证真实 LLM 期限预测、并发恢复、冷存储、高脏页比例或任意后台任务。部署方案可以据此保留提前恢复作为候选，但必须继续单独衡量预测错误带来的提前驻留、重复恢复和额外 I/O 成本。
